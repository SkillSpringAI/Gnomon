# Architectural Invariant Verification Map

**Baseline:** C1 review of implementation HEAD `6be538ed6b32107c0ba69dacb73e8c057d55386b`. The invariant definitions live in the maintained [architecture overview](../architecture/overview.md#architectural-invariants). This map identifies existing executable evidence by its tested boundary; it does not claim a separate complete test for every normative sentence. The committed C1 regression run and its limits are recorded in [implementation status](implementation-status.md) and the [completion record](../development/c1-documentation-authority-baseline.md).

| ID | Invariant | Existing executable evidence | Refactoring implication |
|---|---|---|---|
| INV-01 | Governed mutation is fail-closed | **Bounded:** [security transition tests](../../tests/integration/test_security_state_transitions.py) reject missing/stale/unauthorized state; [interruption ordering tests](../../tests/integration/test_interruption_ordering.py) reject missing/corrupt authority. | Retain fresh authority reads and denial paths at every governed write; extend evidence to any extracted boundary. |
| INV-02 | Durable before consequential external dispatch | **Bounded:** [provider lifecycle tests](../../tests/integration/test_provider_lifecycle.py) cover reservation/dispatch, expiry and crash cases; [cycle recovery tests](../../tests/integration/test_cycle_recovery.py) cover attempt creation failure and retained progress. | Keep commit before provider generation or runner adapter work; preserve unknown outcomes after dispatch. |
| INV-03 | Do not hold governed database authority across external work | **Bounded:** [cycle recovery tests](../../tests/integration/test_cycle_recovery.py) let operator recovery complete while a source/agent call is held; [provider lifecycle tests](../../tests/integration/test_provider_lifecycle.py) exercise dispatch and authority revocation around provider work. No universal lock-duration test exists. | Release governing locks before calls, then reacquire and revalidate before mutation. |
| INV-04 | Governed state and required audit are atomic | **Bounded:** [security transition](../../tests/integration/test_security_state_transitions.py), [interruption closure](../../tests/integration/test_interruption_ordering.py), and [protected restoration](../../tests/integration/test_recovery_restoration_service.py) tests inject audit failure and assert rollback. | Keep each required audit under the same transaction owner as its governed mutation. |
| INV-05 | Execution authority is attempt-bound | **Bounded:** [source and agent late-return tests](../../tests/integration/test_cycle_recovery.py) reject late writes after recovery and resumption; [interruption ordering tests](../../tests/integration/test_interruption_ordering.py) reject foreign or terminal attempt closure. | Carry and recheck the exact durable attempt at each result write. |
| INV-06 | Operator recovery is freshness-bound | **Executable:** [stale recovery fingerprint test](../../tests/integration/test_cycle_recovery.py) rejects recovery after progress changes. | Preserve the observed-progress comparison under the recovery transaction. |
| INV-07 | Authority restoration is asymmetric | **Bounded:** [security transition tests](../../tests/integration/test_security_state_transitions.py) enforce recovery-qualified actor/reason/capability checks; [bootstrap](../../tests/integration/test_authority_bootstrap.py) and [restoration tests](../../tests/integration/test_recovery_restoration_service.py) require the protected path while the bootstrap fence is pending. | Do not turn a pending bootstrap fence into an ordinary state transition. |
| INV-08 | Authority dimensions remain separate | **Combined bounded evidence:** [bootstrap tests](../../tests/integration/test_authority_bootstrap.py) preserve raw state/epoch while changing effective state; [epoch replacement tests](../../tests/integration/test_authority_epoch_replacement_service.py) reject old-epoch current use; [cycle recovery tests](../../tests/integration/test_cycle_recovery.py) bind the separate progress fingerprint. No single test proves the whole taxonomy. | Keep state, fence, epoch, attempt, and fingerprint as separate fields and checks. |
| INV-09 | Governed historical evidence remains append-only where specified | **Partial:** [memory rollback tests](../../tests/integration/test_memory_rollback.py) retain original journal history; [source-dependence contract tests](../../tests/integration/test_source_dependence_contract.py) enforce immutable application history and fail on broken chains; [persistence invariant tests](../../tests/integration/test_persistence_invariants.py) reject task deletion with retained audit. Privileged database-owner tampering is outside these guarantees. | Preserve append-only application APIs and reviewed database restrictions; do not claim cryptographic tamper resistance. |
| INV-10 | Execution implementations remain explicit | **Design/structure invariant:** separate source, provider, and agent implementations exist, but no executable test specifically rejects a generic runner or workflow engine. | Keep their orchestration explicit; extract only shared narrow primitives when tests preserve each path's authority and lifecycle semantics. |
| INV-11 | Infrastructure requirements must be explicit | **No direct invariant-specific executable evidence identified.** The current architecture names PostgreSQL as its reference durable store; future contract/assembly checks are a recommendation, not existing coverage. | State durable infrastructure dependencies at composition boundaries before changing persistence ports. |
| INV-12 | Reconstruction does not manufacture trust | **Bounded:** [reconstruction integration tests](../../tests/integration/test_database_reconstruction_integration.py) enter recovery with fresh context and retain the fence on capture failure; [epoch replacement tests](../../tests/integration/test_authority_epoch_replacement_service.py) require atomic restoration and rotation. Real restore cases depend on PostgreSQL tools. | Keep import separate from governed recovery entry and preserve the restrictive and failure fixtures. |

“Executable” means an existing test exercises the stated boundary; “bounded” and “partial” limit the claim to those paths. Design or future recommendations are not counted as coverage. A later refactor must update this map when its implementation or verification boundary changes.
